# 첫 실행 설정과 탭 없는 사용량 수집

## 구현과 검증 범위

최초 팝업에서 ChatGPT·Claude·Gemini를 체크박스로 선택하고 호스트 권한을 한 번에 요청합니다. 서비스 탭이 없는 경우에는 기존 브라우저 로그인 쿠키로 워커에서 사용량을 조회하도록 구현했습니다. 기존 수집기·파서·로컬 스냅샷·10분 주기·중복 요청 병합·백오프를 재사용합니다.

기존 열린 탭 수집은 사용자가 성공을 확인했습니다. 새 워커 경로는 합성 응답과 Chrome API mock으로 검증하며 **실제 로그인한 Chrome에서 성공을 확인하지 않았습니다**. 호스트 권한이 있어도 SameSite·쿠키 설정·서비스 보호 정책에 따라 탭 없는 요청이 거절될 수 있습니다. 실행한 검사와 결과는 [validation.md](validation.md)에 기록합니다.

## 최초 서비스 선택

- 모든 서비스가 꺼져 있고 세 호스트 권한도 없을 때 초기 설정을 표시합니다. 세 서비스는 기본 선택되어 있고 하나 이상 선택해야 시작할 수 있습니다.
- 사용자의 클릭 안에서 선택한 호스트만 하나의 `chrome.permissions.request`로 요청합니다. 승인 후 해당 서비스들을 켜고 갱신하며 취소하면 켜지 않습니다.
- 새 권한의 승인 이벤트를 워커가 처리하므로 Chrome 승인 창 때문에 팝업이 닫혀도 활성화가 이어집니다. 활성화 요청이 겹치더라도 기존 중복 병합과 갱신 기한을 적용합니다.
- 한 서비스라도 켜져 있거나 권한이 있으면 기존 카드별 켜기·끄기·권한 철회를 사용합니다. 별도 초기 설정 완료 필드를 저장하지 않습니다. 꺼진 기존 서비스를 워커 재시작으로 다시 켜지 않습니다.
- `enable-many` 메시지는 허용된 팝업에서만 처리하며 지원 제공자·중복·추가 필드를 검사합니다. 승인이 없는 제공자를 메시지만으로 켤 수 없습니다.

## 수집 경로 선택

1. 먼저 제공자의 기존 호스트 권한을 확인합니다. 권한이 없으면 네트워크 요청을 하지 않습니다.
2. 실행할 수 있는 서비스 탭이 있으면 기존 MAIN-world 경로를 사용합니다. 여러 탭이 있으면 마지막 활성 창을 우선하여 한 탭만 선택합니다.
3. 정지·폐기된 탭만 있으면 탭 확인 안내를 반환합니다. 선택한 탭의 요청이 실패해도 다른 탭·다른 계정·기본 쿠키 세션으로 재시도하지 않습니다.
4. 해당 서비스 탭이 실제로 하나도 없을 때만 워커 수집을 사용합니다. 자동으로 탭이나 오프스크린 문서를 만들지 않습니다.

워커 요청은 번들의 고정 서비스 URL만 대상으로 `credentials: include`, `cache: no-store`, `redirect: error`를 사용합니다. 쿠키는 Chrome이 처리하며 확장이 쿠키 값을 읽거나 Cookie 헤더를 만들지 않습니다. 새 Chrome 권한은 없습니다.

| 서비스 | 탭 없는 요청 | 기존 데이터와의 관계 |
| --- | --- | --- |
| ChatGPT | `/api/auth/session`의 현재 세션 → `/backend-api/wham/usage`, 필요 시 기존 읽기 전용 티켓 상세 GET | 같은 `chatgpt` 스냅샷을 사용하며 Codex도 같은 결과 표시. 세션 bearer는 요청 함수의 메모리에서만 사용 |
| Claude | `/api/organizations` → 단일 조직의 `/usage?cedar_ember=1` | 기존 파서·티켓 실패 격리·복수 조직 거부 유지. 조직 ID는 수집 함수 밖에 저장하지 않음 |
| Gemini | 고정 `/app` bootstrap → `jSf9Qc([])`, 선택적 `otAQ7b([])` | 기존 RPC 프레임·사용률·초기화·정책 파서 재사용. 기본 Google 쿠키 계정만 사용 |

## Gemini bootstrap 경계

공개 참고는 Claude Tuner 커밋 [`9b94ac3c412732d88cc5a570f0dfe0603d1fc71c`의 `bg/api-gemini.js` 217–282행](https://github.com/chaehyun2/claudetuner/blob/9b94ac3c412732d88cc5a570f0dfe0603d1fc71c/bg/api-gemini.js#L217-L282)입니다. `/app`과 `WIZ_global_data.SNlM0e` 계약을 참고해 TypeScript로 독립 구현했으며 원격 함수나 비공개 `vendor-ai` 모듈을 실행하지 않습니다. 원본은 MIT, Copyright (c) 2025–2026 Claude Tuner Contributors입니다.

- `/app`의 `text/html` 응답을 스트림으로 읽습니다. 전체 응답 상한은 4MiB, script 후보는 256×1024 코드 단위입니다. 실제 script 문맥의 JSON 할당만 해석하며 HTML 주석·문자열·실행되지 않는 컨테이너의 비슷한 토큰을 인증정보로 인정하지 않습니다.
- `WIZ_global_data`의 `SNlM0e`만 추출하여 요청 함수의 메모리에 둡니다. 토큰을 찾으면 스트림을 취소합니다. JSON을 파싱할 뿐 원격 JavaScript·HTML을 실행하지 않습니다. 대화·프로필·계정 목록을 해석하거나 수집하지 않습니다.
- bootstrap부터 RPC까지 하나의 15초 수집 기한을 공유합니다. 조기 종료·초과 크기·시간 초과에는 읽기와 요청을 중단합니다. RPC 응답에는 기존 1MiB 상한을 유지합니다.
- 정책 RPC로 요금제를 확인한 경우 `/app`의 토큰을 한 번 더 확인하여 수집 중 맥락 변경을 검사합니다. 이 선택적 확인은 최대 3초이며 실패·불일치이면 요금제만 제외하고 이미 검증한 사용량을 유지합니다. 토큰 일치는 계정 ID를 증명하지 않으므로 모든 종류의 계정 전환을 감지한다고 주장하지 않습니다.
- 외부 출처·로그인 리다이렉트는 따르지 않습니다. 토큰을 확인할 수 없으면 탭 확인 안내를 남기며 임의 HTML 문자열 검색이나 인증 우회로 대체하지 않습니다.
- 요청 토큰·원본 HTML·원본 정책은 저장·로그·UI 반환하지 않습니다. 상태와 기존 정규화 사용량만 공통 파서·스냅샷 경로로 전달합니다.

열린 Gemini 탭의 `/u/1`·`authuser=1` 등 비기본 계정은 기존대로 지원하지 않습니다. 이런 탭이 있다는 이유로 기본 계정을 대신 조회하지 않습니다. 탭이 없는 경우의 쿠키 기본 계정과 사용자가 기대한 계정의 일치는 실제 브라우저에서 확인해야 합니다.

## 압축 팝업

기본 폭은 600px입니다. 서비스 제목·요금제·버튼을 같은 줄에 배치하고, 각 한도의 사용률·작은 진행 막대·초기화를 가로로 묶습니다. 티켓별 수량·만료는 각각 유지하면서 가로 배치 후 줄바꿈합니다. 기존 밝은/어두운 테마·로고·표시 문구와 입력창 표시줄 크기는 유지합니다.

서비스 제목은 기존 모양을 유지하면서 클릭이나 키보드로 공식 홈을 새 탭에 여는 링크입니다. 마우스 커서만 포인터로 바꾸며 별도 사이트 열기·새로고침 버튼은 두지 않습니다. 사용량은 10분 자동 수집과 팝업 열기 갱신을 사용하며 최소 60초 간격과 백오프를 유지합니다.

좁은 화면에서는 초기화와 버튼을 다음 줄로 옮깁니다. 제한이나 티켓을 잘라 숨겨 스크롤을 줄이지 않으며 항목이 많으면 필요한 세로 스크롤은 남습니다. 600px 기본 폭과 390/320px 좁은 화면을 합성 Chromium에서 확인합니다.

사용자는 `202610142353` 설치 후 “훨씬 잘 보인다”고 압축 팝업의 가독성 개선을 확인했습니다. 이 확인은 탭 없는 실제 API 수집이나 최초 권한 승인 흐름의 검증을 의미하지 않습니다.

## 실제 브라우저에서 확인할 사항

- 처음 설치한 프로필에서 선택한 서비스만 권한 승인 창에 나타나는지, 취소와 팝업 종료 후 활성화가 올바른지 확인합니다.
- 각 서비스에 로그인한 뒤 해당 서비스 탭을 모두 닫고 자동 수집을 기다리거나 팝업을 다시 열어 공식 사용량 화면과 사용률·초기화를 대조합니다. 최소 60초 간격과 재시도 대기를 지난 수집 결과인지 확인합니다. 서비스별 쿠키·보호 정책에 따라 탭이 필요할 수 있습니다.
- 열린 탭을 다시 사용했을 때 그 탭의 맥락을 우선하는지, 로그아웃·쿠키 만료·계정 또는 Claude 조직 변경 때 이전 요금제·티켓을 잘못 합치지 않는지 확인합니다.
- Gemini는 기본 Google 계정을 사용하며 bootstrap·정책 맥락 확인이 실패해도 확인된 사용량을 유지하는지 확인합니다. 여러 계정을 자동 순회하지 않습니다.
- 초기 설정·평상시 팝업의 스크롤과 키보드 이동을 실제 Chrome 창 크기에서 확인합니다.

PR 생성·수정과 소스 푸시·병합은 해당 작업에서 사용자가 명시적으로 요청한 대상과 범위에 따라 수행합니다. 이전 작업의 요청을 새 수정에 이어서 적용하지 않으며 설치 ZIP 게시 승인은 이와 분리합니다.
