# 권한과 개인정보

| 권한 | 용도 | 대안과 선택 이유 |
| --- | --- | --- |
| storage | 설정, 최신 정상 사용량·오류·재시도 시각 저장 | 메모리는 MV3 재시작 시 사라짐. 이력·원본 응답·인증·계정 식별자 없음 |
| alarms | 10분 갱신 및 worker 재시작 복구 | 상시 서비스 워커/setInterval 대신 Chrome 예약 |
| scripting | 선택 호스트 승인 후 표시줄, Work / Codex·Claude의 고정 GET, 일반 ChatGPT의 init 메타데이터 관찰 | 쿠키 추출·대화/이력 조회 없이 기존 세션 사용. 번들 안의 코드만 실행 |
| optional_host_permissions | https://chatgpt.com/*, https://claude.ai/* | 사용자가 선택. 일반 ChatGPT 관찰과 플랜 수집은 동일 호스트 권한을 공유하며 스냅샷은 분리. 일반 채팅·Codex 표시줄은 같은 플랜 스냅샷을 참조 |

`tabs`, `cookies`, `activeTab`, `webRequest`, `<all_urls>`와 Gemini 호스트 권한은 요청하지 않습니다. 승인한 호스트 권한으로 해당 탭의 URL을 식별할 수 있습니다. 배지는 Chrome action의 `tabId`별로 설정하며 일반 ChatGPT·Codex에서는 같은 플랜 데이터, Claude에서는 Claude 데이터를 사용합니다. 지원하지 않는 사이트나 URL을 읽을 권한이 없는 탭은 빈 배지이며 전역 기본 숫자도 비웁니다. 탭 ID를 조회하는 데 `tabs` 권한은 필요하지 않고, 조회한 ID·URL은 저장하거나 전송하지 않습니다. 사이트의 실패·오래된 값을 다른 서비스의 정상 값으로 바꾸지는 않습니다.

선택 호스트 권한의 새 승인은 해당 카드 소스의 활성화도 의미합니다. Chrome의 권한 승인 이벤트를 백그라운드가 처리하므로 승인 중 팝업이 닫혀도 두 번째 켜기 클릭이 필요하지 않습니다. Chrome 설정에서 새로 승인할 때도 동일합니다. 실험적인 일반 채팅 관찰은 자동으로 켜지 않으며 기존 권한만 유지한 채 꺼둔 서비스는 재시작 때 활성화하지 않습니다.

여러 Chrome 창에서는 마지막 활성 창의 허용된 서비스 탭을 수집 대상으로 우선합니다. 실패 후 다른 탭/계정을 순회하지 않습니다. **개발 빌드**의 접힌 진단은 빌드 버전·서비스별 켜기/권한/표시 설정·상태/오류 코드·확인/수집/재시도 시각을 로컬에서 표시합니다. 사용자가 진단 표시·복사를 누르면 현재 활성 사이트의 구조 진단도 요청합니다. 반환 항목은 사이트 종류, content script 응답 여부, 입력 요소·iframe·표시줄 개수(각각 최대 10,000), 표시 대상 탐색 성공, 표시줄 가시성입니다. `build:release` 또는 `--release`로 만든 배포용에서는 진단 UI·핸들러를 비활성화합니다.

구조 진단은 원본 DOM·클래스명·텍스트·URL·계정·인증·대화·원본 응답·사용량 항목명을 포함하지 않습니다. 동일 확장의 팝업에서 보낸 요청만 content script가 허용하며 팝업도 반환 타입·범위를 다시 검증합니다. iframe 내부는 접근하지 않고 개수만 셉니다. 진단은 별도 저장·자동 전송되지 않으며 사용자가 눌렀을 때만 복사합니다. `clipboardWrite` 권한도 없으며, 복사 API가 차단되면 읽기 전용 텍스트를 선택하여 직접 복사할 수 있게 합니다.

권한 승인/철회는 해당 사이트 전체에 적용되므로 ChatGPT 카드에서 철회하면 일반 ChatGPT 관찰과 Work / Codex도 접근 권한을 잃습니다. 수집 설정과 저장소는 데이터별, 표시줄 설정은 일반 채팅·Codex·Claude 화면별로 구분합니다. 일반 채팅 표시줄은 `work_codex` 수집 설정과 `strips.chatgpt`를 따르므로 실험적인 일반 ChatGPT 관찰을 꺼도 사용할 수 있습니다. 현재 팝업은 **ChatGPT·Claude** 두 카드만 제공하며 **ChatGPT 카드의 데이터 출처는 플랜 `work_codex`**입니다. 실험적인 일반 Chat 수집 카드는 표시하지 않지만 내부 관찰·저장 계약은 유지합니다. 사이트당 표시용 isolated script는 하나만 등록하며, 기존 설정에서 일반 ChatGPT 관찰이 활성화된 경우 MAIN-world 관찰기 하나를 별도로 등록하고 표시줄을 꺼도 갱신·정리 연결을 유지합니다.

카드의 상세·선택 메뉴·마지막 수집·다음 갱신 시각은 팝업에서 제거하며 서비스 관리 버튼은 유지합니다. 설정은 일반 ChatGPT·Codex·Claude 입력창 표시 체크박스 세 개입니다. 과거의 수동 배지 대상·한도 선택값은 저장 계약 호환을 위해 남아 있어도 표시에서는 사용하지 않습니다. 입력창·배지는 실제 응답의 유효 사용률 중 최댓값을 고르고 동률은 응답 순서를 유지합니다. 기간·모델별 원본 항목은 각각 보존하며 합계나 전체 모델 차단 여부를 추정하지 않습니다. 추가 권한·수집 요청은 필요하지 않습니다.

일반 ChatGPT 관찰기는 사이트의 `fetch`를 투명하게 감싸 동일 출처의 정확한 `/backend-api/conversation/init` JSON 응답만 처리합니다. 원래 요청·응답 Promise는 그대로 반환하며 추가 요청을 만들지 않습니다. 요청 body/headers, 대화·이력·SSE는 읽지 않습니다. 응답에서 기능명·잔여 수치·초기화와 관찰 시각만 페이지 메모리에 남기고 확장 측에서 다시 검증합니다. 페이지 이벤트에는 갱신/종료 신호만 있고 사용량·자격증명 payload는 없습니다. 꺼짐·권한 철회 시 fetch 훅과 캐시를 정리하며, 계정 전환 후에는 사이트를 새로고침해야 합니다.

쿠키를 읽거나 인증정보를 저장하지 않습니다. Work / Codex 요청의 세션 bearer는 MAIN-world 함수 내부에서만 사용하고 반환하지 않습니다. Claude 조직 UUID도 조회 함수 내부에만 존재합니다. 저장하는 것은 최신 정규화 제한 항목·수집 시각·상태·설정뿐입니다. 동일 Chrome 프로필에서 계정을 바꿨다면 새로 갱신해야 합니다. 이전 값은 실패/만료 시 오래된 정보로 표시하며 계정 합산이나 자동 전환은 하지 않습니다.

표시줄은 입력 요소·중지 버튼과 배치할 래퍼/footer의 **존재·구조·레이아웃**을 검사합니다. 입력/대화 텍스트·첨부·이력은 읽지 않습니다. Claude는 사용자가 제시한 `bg-surface-3` 내부의 `relative w-full min-w-0` 또는 `mni-w-0` 래퍼 뒤에, Codex는 `ComposerLayoutFooter-` 접두사 클래스의 footer 내부 마지막 자식으로 배치합니다. 편집 가능한 영역 안에는 삽입하지 않습니다. Codex의 가로 flex footer에서는 표시줄이 다음 행에 들어가도록 필요한 경우 줄바꿈 속성만 조정하며, 제거할 때 사이트가 이후 변경한 값을 덮어쓰지 않습니다. 사용자는 `202610141801`에서 ChatGPT·Claude의 홈·채팅 위치를 확인했지만 Codex 표시에는 실패했습니다. 이번 Codex 판별 보강 후 실제 로그인 화면 검증은 남아 있습니다.

사용자 계정에서 Codex의 `/codex/cloud`가 `https://chatgpt.com/`로 이동한 뒤 표시 대상 탐색에 실패했습니다. 이를 위해 같은 허용 호스트에서 명시적인 `ComposerLayoutFooter-` 구조가 있으면 표시 맥락을 Codex로 판별합니다. URL·프로토콜·호스트 권한·메시지 발신자 검증은 그대로이며, 다른 도메인이나 iframe에 대한 권한을 넓히지 않습니다. SPA 전환 시 표시 위치를 다시 판별하고 이전 표시줄을 제거합니다.

일반 채팅과 Codex 입력창은 **한 `work_codex` 플랜 스냅샷**을 외곽선 없이 표시합니다. 80×6px 진행 막대와 `사용량: 15%`, `🕒 사용량 초기화: 10/16(금) 09:05, 2d 1h 남음` 묶음을 레이아웃 간격으로 나누며 두 묶음 사이에 쉼표를 넣지 않습니다. 없는 값을 0% 진행 막대로 만들지 않습니다. 사용자 설정 문구의 “Chat 대화는 사용량에 포함되지 않습니다”라는 구분을 유지하며, 표시 위치를 이유로 일반 ChatGPT 수집값으로 저장하거나 합산하지 않습니다. 페이지의 임의 window 메시지를 사용량 원본으로 신뢰하지 않고 Chrome runtime 요청·응답을 검증합니다. DOM에는 textContent로 삽입합니다.

사용자 제공 앱 아이콘은 `assets/logo.png`를 16/32/48/128px로 리사이즈해 확장에 포함한 로컬 PNG입니다. 표시줄은 별도 제공한 `assets/logo-20x20.png`의 data URL을 빌드에 포함하여 외부 서버 이미지 요청이나 web_accessible_resources를 추가하지 않습니다. 아이콘 취득에 사용한 GitHub URL은 개발 시에만 접근하며 확장 런타임은 GitHub에 연결하지 않습니다.

권한 철회 시 URL을 읽지 않고 탭 ID로 철회된 허용 호스트 목록과 정리 신호를 보냅니다. 표시줄은 자신의 확장 ID에서 온 신호이고 현재 사이트의 권한이 철회된 경우에만 종료합니다. 이미 권한을 잃어 상태 조회가 거절되어도 정리할 수 있으며, 중지 전에 시작한 조회의 늦은 응답으로 다시 표시되지 않습니다. 일반적인 일시 통신 실패에는 이전 표시를 유지하고 로컬 상태 조회를 재시도합니다. Chrome이 이미 실행한 content script 자체를 회수할 수는 없으므로 표시 노드와 핸들러를 정리합니다. 기존 사이트 입력 기능은 변경하지 않습니다. API 응답·토큰·cookie·프롬프트·예외 body를 로그하지 않습니다. 광고·원격 분석·임의 서버 전송·코드 로드는 없습니다.
